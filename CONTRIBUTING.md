# Contributing to Cosmic Ext Thunderbolt

Thank you for your interest in contributing! **Cosmic Ext Thunderbolt** aims to make Thunderbolt™ management on the COSMIC™ Desktop secure, transparent, and user-friendly.

Whether you want to fix a bug, add a feature, improve documentation, or translate the interface, your help is welcome.

## 🛡️ Core Principles

Before contributing, please familiarize yourself with our [Design Philosophy](./DESIGN_PHILOSOPHY.md). Key takeaways:
*   **Safety First:** Thunderbolt grants DMA access. Any code modifying device state (authorization, firmware) must include "friction" (confirmations, checks) to prevent accidental data loss or hardware bricking.
*   **Transparency:** We expose hardware reality (topology, speeds, security layers) rather than hiding it behind oversimplified abstractions.
*   **No Magic:** We rely on documented kernel behaviors (`sysfs`, `boltd`, `fwupd`) rather than heuristic guesswork.

## 🚀 Getting Started

### 1. Prerequisites
Ensure you have the necessary tools installed:
*   [Rust Toolchain](https://rustup.rs/)
*   [just](https://github.com/casey/just) (command runner)
*   COSMIC Desktop Environment (for running/testing the applet)
*   `boltd` daemon running on your system

### 2. Clone and Build
```bash
git clone https://github.com/YOUR_USERNAME/cosmic-ext-thunderbolt.git
cd cosmic-ext-thunderbolt
just build-debug
```

### 3. Testing Without Hardware (Mock Mode)
You **do not** need physical Thunderbolt hardware to contribute to the UI or logic. We include a **Mock Backend** to simulate various scenarios (insecure security, auth errors, complex topologies).

**Run with simulated data:**
```bash
just run-mock
```
This compiles with the `mock` feature and injects test data. You can modify `src/mock_bolt_dbus.rs` to create new test scenarios (e.g., specific error states or long device lists).

> **Note:** The mock code is strictly excluded from production builds.

## 🧩 How to Contribute

### 🐛 Reporting Bugs
Please open an issue with:
*   **Steps to reproduce.**
*   **Expected behavior** vs. **Actual behavior**.
*   **Logs:** Run the applet from a terminal to capture `RUST_BACKTRACE=full` output if it crashes.
*   **System Info:** COSMIC version, `boltd` version, and Thunderbolt hardware details.

### 💡 Feature Requests
We welcome ideas, but please check the [TODO.md](./TODO.md) first.
*   Features presented there are already in the roadmap.
*   For new ideas, explain the **use case** and how it aligns with our **Safety** and **Transparency** principles.

### 🧑‍💻 Submitting Code (Pull Requests)
1.  **Fork** the repository and create a branch (`feature/my-feature` or `fix/my-bug`).
2.  **Code Style:** We follow standard Rust idioms. Run `just check` (clippy) before committing.
3.  **Testing:**
    *   Ensure your code compiles in release mode: `just build-release`.
    *   If you touch UI logic, test it with `just run-mock`.
    *   If possible, test on real hardware.
4.  **Commit Messages:** Use clear, descriptive messages (e.g., `feat: add IOMMU detection logic`, `fix: prevent panic on missing UID`).
5.  **Open a PR:** Describe your changes and link any relevant issues.

### 🌍 Translations
We use [Fluent](https://projectfluent.org/) for localization.
1.  Navigate to the `i18n/` directory.
2.  Copy the `en/` folder to your language code (e.g., `fr/`, `de/`, `ja/`).
3.  Translate the values in the `.ftl` files. **Do not change the message identifiers (keys).**
4.  If a translation is missing, the app will fallback to English automatically.
5.  Submit your changes via PR.

## 📐 Architecture Overview

*   **`src/thunderbolt.rs`**: Core data models (`BoltDevice`, `BoltState`) and the subscription entry point.
*   **`src/bolt_dbus.rs`**: The real backend interacting with `boltd` over D-Bus using the autogenerated interface `src/bolt_proxy.rs`.
*   **`src/mock_bolt_dbus.rs`**: The simulated backend for testing (guarded by `#[cfg(feature = "mock")]`).
*   **`src/ui_types.rs`**: UI-specific helpers (icon mapping, formatting) to keep the core model clean.
*   **`src/config.rs`**: Advanced users configuration options.
*   **`src/app.rs`**: The COSMIC applet logic, UI state management, and rendering.
*   **`src/main.rs`**: Entrypoint, launches the applet.
*   **`i18n/`**: Localization files.

## 🔒 Security Considerations

Since this tool interacts with low-level hardware:
*   **Never** commit hardcoded secrets, keys, or paths specific to your machine.
*   **Always** validate inputs before passing them to D-Bus or `sysfs`.
*   **Destructive actions** (like firmware flashing or force de-authorization) must be implemented with explicit user confirmation and safety checks (e.g., preventing flash of an active display device).
